# Implementation Plan: Optimización y Cobertura de Actualizaciones en Tiempo Real

**Branch**: `004-realtime-update` | **Date**: 2026-05-26 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/004-realtime-update/spec.md`

## Summary

Centralizar y optimizar las conexiones de Supabase Realtime a través del hook personalizado `useSupabaseRealtime` mediante un mecanismo de registro en memoria que multiplexe las suscripciones. En lugar de crear un canal WebSocket independiente por cada instancia de hook, se mantendrá un único canal activo por cada tabla de base de datos (`clientes`, `refacciones`, `proyectos`, etc.), distribuyendo los eventos a los distintos callbacks suscritos.
Asimismo, se expande la cobertura de tiempo real a los módulos de inventario (`CompraRefacciones` y `VentaRefacciones`), al catálogo auxiliar de asignación en `ProyectosModule` (mecánicos, vehículos, clientes), y a las pantallas orientadas al cliente final (`Ticket.jsx` y `HistorialTickets.jsx`), integrando además un indicador visual del estado de conexión WebSocket.

## Technical Context

**Language/Version**: JavaScript (React 18+, Vite)  
**Primary Dependencies**: `@supabase/supabase-js`, `react-dom`  
**Storage**: Supabase (PostgreSQL with Realtime Replication enabled)  
**Testing**: Manual viewport simulator verification, Vite production bundle check  
**Target Platform**: Web browsers (Responsive Desktop & Mobile Viewports)  
**Project Type**: SPA Web Application  
**Performance Goals**: Latencia de sincronización < 2 segundos, límite estricto de **1 WebSocket channel activo por tabla** en toda la sesión  
**Constraints**: RLS (Row Level Security) transparente en la comunicación del canal, evitar re-renders innecesarios mediante agrupamiento (debounce) de eventos si la base de datos recibe ráfagas de escrituras  
**Scale/Scope**: 1 hook global optimizado, 6 módulos actualizados en tiempo real y 1 indicador de estado de conexión en la TopBar
